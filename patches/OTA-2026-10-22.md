# Virgo OTA recovery-size repair and repack

- Date: 2026-10-22
- Product: LineageOS 21 / Android 14, `lineage_virgo-ap2a-userdebug`
- Result: `mka bacon -j8` completed and generated a valid signed ROM ZIP.

## Failure and cause

The supplied log at `/run/media/root/c309382c-cda1-4153-ad35-de1784b9715e/virgo-out/error.log` ended during OTA creation with:

```text
common.ExternalError: recovery size (16619520) is 99.06% of limit (16777216)
```

The recovery partition is fixed at 16 MiB. The OTA releasetools applies a stricter 99% safety threshold, so the 16,619,520-byte image was 10,076 bytes over that threshold. This was a final packaging failure; the earlier build had already generated target-files and images.

## Source patch

Added `device/xiaomi/virgo/0007-trim-recovery-ota-image.patch`. It adds this post-copy Recovery preparation rule to `BoardConfig.mk`:

```make
BOARD_RECOVERY_IMAGE_PREPARE = rm -f $(TARGET_RECOVERY_ROOT_OUT)/system/bin/mkfs.erofs
```

EROFS is read-only, so Recovery needs its checker (`fsck.erofs`) but not the formatter used to create images. The Android system image still contains `/system/bin/mkfs.erofs`; only the Recovery copy is removed. The independent Recovery density and UI resources stay unchanged.

The patch is stored under the source path grouping at `device/xiaomi/virgo/patches/device/xiaomi/virgo/`. All patches replayed with `bash device/xiaomi/virgo/patches/check.sh`; `git -C device/xiaomi/virgo diff --check` passed.
