# Off-mode charging diagnosis — 2026-10-22

## Observed failure

With the phone connected to USB, `adb reboot -p` reproduced the user's symptom:
the display remained on the OEM logo and ADB disconnected. The phone returned to
Android after the user held the power key. No complete ROM build or post-fix
flash has been performed.

The existing system image already contains `/system/bin/charger`, the charger
resource images, the health HAL, and the MSM8974 charger-monitor binary. The
product package expansion also includes `charger` and `charger_res_images`, so
adding those package names again would not address this failure.

## Root cause in the captured boot log

`/root/桌面/virgo-features-20261022/charger-last-kmsg.txt` records first-stage
init mounting the system partition as the root filesystem and switching root
to `/system`. Later, the generic `/system/etc/init/hw/init.rc` starts the
`charger` class before MSM8974 vendor charger initialization runs. The legacy
`init.qcom.rc` charger action then mounts that same system partition again at
`/system`. Immediately afterward, init reports `Too many symbolic links`
starting `/vendor/bin/*`, `/system/bin/*`, and the charger services; the first
charger process exits with status 1.

## Source patches

- `system/core/0001-defer-charger-class-start-until-platform-init.patch` removes
  the premature generic charger-class start. MSM8974's vendor init starts that
  class after its charger setup.
- `device/xiaomi/msm8974-common/0004-fix-offmode-charger-system-as-root.patch`
  removes the obsolete wait and duplicate system mount from the charger action.

`bash device/xiaomi/virgo/patches/check.sh` validates that both patches are
replayable with the existing patch series. The remaining functional check is to
build and flash the user's next ROM, then confirm the phone displays the charge
animation and can boot Android from the charger screen.
